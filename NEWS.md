# markermd 0.1.0

* Initial version.
* Added `parse_project()`, a headless per-repository parse check, and the bundled `markermd-fix-parsing` skill that repairs submissions the strict q2r parser rejects on a `grading-fixes` branch.
* The bundled skills now ship in two sets, for Claude Code (`inst/skills/claude/`, installed to `.claude/skills/`) and Codex (`inst/skills/codex/`, installed to `.agents/skills/`); `init_project()` gained an `agents` argument (default: both) and `markermd_skills_path()` an `agent` argument.
* `mark()` now opens on an Assignments tab holding one table with a row per repository: its folder, GitHub, report and source links, its validation status and grading progress, and its score per question and in total as entered through the rubric, with the graded count, mean, median and standard deviation per question pinned beneath as summary rows. The table filters by name and status, sorts by any column, and updates as grading proceeds. The validation results moved to their own Validation tab, with a repository selector kept in step with the rest of the app; clicking a repository's validation marker in the table opens it there, and clicking a score opens that repository and question in the Rubric tab. Repository names in the table are plain text rather than selection buttons. The table is a `reactable` (added to Imports); `gt` is no longer a dependency.
* The Validation tab's repository selector now shows each repository's count of passed questions, and a question selector beside it lists each question with a coloured pass or fail mark for the current repository; choosing one scrolls that question's results into view. Each question's results card collapses and expands from a chevron in its header, a collapsed question stays collapsed across repositories, and the document tree in each card is no longer capped in height.
* `mark()` is now permissive about where a repo's rendered report lives: any HTML file named for the repo, or anywhere under a directory named for the repo (`<repo>/`, or `<repo>` plus a delimiter such as ghclass's `<repo>_<artifact-name>/`), is accepted when it is the only one. Previously only three exact layouts were checked, so projects laid out by `ghclass::org_grade_assignment()` showed "No Artifact Available" for every repo. When several HTML files are found for a repo, a heuristic modelled on the ghclass layout picks the most likely report (rendering resource directories such as `*_files/` rank last), a consolidated warning at launch names each affected repo and its choice, and the Content pane shows a notice above the report.
* Rubric items are no longer effectively limited to ten per question. The first ten keep the hotkeys 1-9 and 0; further items are toggled by clicking (their button is blank with a dashed outline). Display order is now stored explicitly in the grading database (`items.position`, schema version 2, migrated in place the first time a project is opened), so reordering items past the tenth survives a restart and export; previously those items always reloaded in insertion order.
* Raw blocks that are nothing but `<!-- ... -->` comments are now their own node kind, `HTML comment`, so rules and filters distinguish `{=html}` write-ups (still `Raw Block`) from skeleton placeholders and repair markers, and `assignment_outline()` no longer counts comments as content.
* Template questions have a `scope`: `"sections"` (the default) targets the selected headings and divs, and `"document"` covers the document as a whole, for problems that belong to no single question (a render setting in the YAML header, global chunk options, a document that does not render). A document-scope question selects no nodes; its filters and rules, if any, evaluate against the whole document. `template()` gained an "Add Document Entry" button, `export_comments()` writes document-scope feedback first, and templates with such a question are written as format 3.1 (3.0 files still load).
* A question's scoring can be marked `optional`: an optional question counts as graded for every repository and scores as if no rubric item were selected until something is recorded, so a document-level question that applies to few submissions needs no selection in the rest and no longer leaves their totals `NA`. It is set from the grade settings popover in `mark()` or with `optional: true` in the rubric YAML (format 1.2, written only when used), stored in `settings.optional` (schema version 4, migrated in place), and marked with a small red dot beside the question's name in the Assignments table.
* The bundled skills record document-level problems once in a document-scope question (0 points, optional, not bounded below zero) added only when a submission needs one, instead of spreading them across questions, and after a `mode = "replace"` rubric import give pairs left with no selection their confirmation item.
* `project_set()` gained `artifacts`, to record the directories of rendered reports (or none) without editing `config.yml`.
* Re-running `init_project()` now keeps the configured artifact directories (dropping any that no longer exist) instead of re-deriving them from every top-level folder, which added working folders such as notes or backups; new folders are listed instead. `rescan_artifacts = TRUE` restores the full rescan, and `overwrite_instructions = TRUE` replaces existing `CLAUDE.md` / `AGENTS.md` files with the packaged versions.
